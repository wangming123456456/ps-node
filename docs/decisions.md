# PS 节点 · 架构决策与协议（v0.2）

> 取代 `规划-v0.1.md` / `设计-v0.1.md` 中与本文冲突的部分。v0.1 的 COM 桥路线已放弃。

## 决策

| 编号 | 决策 | 理由 | 代价 |
|---|---|---|---|
| D1 | 画布侧做插件，PS 侧做 **UXP 插件** | 面板可以放在 PS 里，人在 PS 精修时不用切回画布；图层级能力（batchPlay）后续可扩展 | UXP 需要 Developer Tool 开发、分发需签名 |
| D2 | 中转交给本地 **canvas-agent** 托管（进程复用 `electron/ps-relay.cjs`） | 用户不用单独启动进程，画布打开时自动拉起并注入地址/token | 要改宿主仓库；agent 没跑时插件连不上 |
| D3 | 中转用**零依赖 HTTP 长轮询**（`node:http`） | 宿主打包白名单只包含 `electron/` 与 `web/dist/`，加 `ws` 依赖需要改打包配置；长轮询两端都能用 fetch 实现，延迟毫秒级 | 不是真 WebSocket；超长连接需要自己保活 |
| D4 | 画布插件按**第三方插件（填 URL）**分发 | jsDelivr 直接引用 tag 产物，升级只要改 tag | 仓库必须公开 |
| D5 | 生成走宿主的 `ctx.ai`，ComfyUI **不参与 v1** | 少一个常驻进程、少约 300 行工作流代码；宿主已管好模型和密钥 | 想用本地工作流（LoRA/ControlNet）要等后续版本 |
| D6 | 中继地址与 token 只通过 `window.__RUNTIME_CONFIG__.psRelay` 下发，插件不提供手填入口 | 宿主已有 runtime config 机制，不需要额外 IPC；token 轮换不用改插件 | 插件必须跑在会注入配置的画布页面里 |
| D7 | 只保留固定原子命令（`docs` / `push` / `pull` / `selection`），不提供任意脚本执行端点 | 中继等价于本地操作 PS 的能力，且中继对本地网页开放 | 扩展能力要改代码而不是发任意脚本 |
| D8 | 安全默认值：只绑 `127.0.0.1`、token 必填、画布侧校验 Origin | 中继可以驱动 PS，风险面必须收敛 | 多一次复制 token 的手工步骤 |
| D9 | 画布 **PS 节点只做通道**（取回 / 推送 / 文档 / 中继），生成和改图交给画布现有图片节点；PS 面板的「AI 生成」保留（走反向通道） | 不重复造生成面板，画布无论加什么编辑能力 PS 节点都自动受益；模型/提示词/参数全由宿主面板负责 | 想"在 PS 节点上直接出图"时要多接一个图片节点 |

## 候选方案 v0.3：PS 能力降到图片卡片（选中即预览）

> 状态：**已实施**（画布 `feat/image-edit`；本仓库插件 v0.2.0 已退场）。落地过程中补了一条环境事实见文末。

### 为什么想改

- **补丁在累积**：生成要判 `isPluginImageNode` 才不把 PS 节点改成文字节点、工具条要判 `isPluginImage` 才给图片工具、复制/下载/反推要按 `nodeHasImageContent` 才不哑掉、还要 `editTarget: "self"` 才能原地改。四次都是同一件事——它明明是张图，处处不像图。
- **发现性差**：PS 能力藏在「扩展节点」里，新用户得先学会"建 Photoshop 节点而不是图片节点"。
- **升级摩擦**：改一行画布侧插件就要 build → 同步缓存 → 打 tag → 改文档 URL → 用户重装。而宿主其实早内置了 PS 的一半（`electron/ps-relay.cjs`、`__RUNTIME_CONFIG__.psRelay` 注入、`sendPsPreview()`），插件只贡献了节点渲染和两个按钮。
- **时机**：项目未上线、不要求兼容旧数据，现在迁移最便宜。

### 交互模型

不引入"节点归属"概念，PS 面板永远是**当前选中卡片**的取景器。

| 动作 | 触发 | 结果 |
|---|---|---|
| 选中一张图片卡片 | 自动（防抖 ~200ms） | PS 面板预览区显示这张的缩略图 + 来源标题（卡片名 / 尺寸） |
| 选中多张图片卡片 | 自动 | 预览显示**第一个选中**的那张，角标 `1/5`；其余只参与批量落层（见下） |
| 选中视频 / 音频 / 文本卡片 | 自动 | 面板给提示「这个类型 PS 不支持」，**保留上一张不闪空** |
| PS 面板点「落层」 | 手动（点预览画面） | 按 PS 当前选区把**当前显示的那张**落成图层；**不加按钮，保持现在的隐形点击** |
| PS 面板点「发送画布」 | 手动 | 把 PS 当前画面写回**当前选中**的那张卡片 |
| 画布右键「从 PS 取回」 | 手动 | 和「发送画布」等价，不想切到 PS 面板时用 |
| 画布工具条「推送到 PS」 | 手动 | 显式把图送进 PS；多选时逐张排队落层（批量入口） |

### 命名

- PS 面板两个动作固定叫 **「落层」** 和 **「发送画布」**（取代原来的「落成图层」「取回」说法）。
- **「落层」不加按钮**：保持现在「点预览画面就落层」的隐形交互。多选时点的仍是面板上显示的那一张。
- 「发送画布」是面板上的一个按钮，并且要显示**将写回哪张卡**（`将写回：橘子猫_02`）——面板是被动的，用户可能在 PS 里改图期间在画布上换了选中项。
- 画布侧保留右键 **「从 PS 取回」**，和「发送画布」是同一个动作的两个入口。
- 画布侧保留 **「推送到 PS」**：它是**兜底通道**——实时展示（选中即预览）只是增强，断了/面板后开/节流跳过时，仍然能手动把这张推过去。它和图片工具一样进「更多 → 自定义工具栏」：可勾选隐藏/显示、可排序，不单独造一套开关。

### 多选与批量落层

- 面板预览显示**第一个选中**的那张，角标 `1/5`，点击只落这一张——不做"看到一张、落下五层"。
- 批量落层走画布侧 **「推送到 PS」**：多选时逐张串行推过去，PS 侧**落进一个新建的图层组**（组名带时间），避免五个图层散落。
- 顺序定义：点选 / Shift 点选按**点击顺序**（`Set` 插入序天然满足）；**框选没有点击顺序**，按画布位置兜底——先上后下、同高先左后右。
- **上限 15 张**：超过就整批拒绝，提示「数量达到 15 张上限」，不做"只落前 15 张"——少落了还得数，不如一次说清。
- **逐张串行**：发一张、等这一张的结果、再发下一张。不要一次性把 15 张全排进中继队列——单张上限 8MB（base64），15 张一次性排队最坏是 100MB 级的内存峰值，串行能把它压到一两张。
- **失败自动跳过**：某张失败不影响后面，全部跑完弹一条汇总（`15 张：成功 13，失败 2，跳过 1 —— 「橘子猫_03」推送超时；「logo」失败原因…；「花絮.mp4」视频卡片不支持`），PS 面板日志里留每张的明细。
- **混进视频/音频卡**：按跳过处理，不报错、不中断，但要在汇总里写明原因（`视频卡片不支持`），不能静默省略。

### 拒绝与空态

- **目标卡正在生成**：「发送画布」直接拒绝，面板提示 `该卡片正在生成，稍后再试`，不排队也不覆盖——生成中的卡被写回会打架。
- **预览区空态按原因分开说**，不要一句笼统的"未连接"：
  - 连不上中继（23310 没起来）→ `中继未启动：先打开画布页面（或启动画布智能体）`
  - 中继在但画布页没连 → `画布页面没连上中继，刷新一下画布页`
  - 都连上了但没选卡片 → `在画布上选一张图片卡片`
- 这三层判断现成可得：`/api/health` 的 `canvas.connected` 区分前两种，第三种看当前有没有 track 到的卡片。

### 设置去哪了

- 节点上的齿轮「设置」退场，内容并进 **「配置 → PS 节点」**（和现有「配置 → ComfyUI」并列一页）：
  - 输出尺寸（原 `maxEdge`，取回/发送画布时用）；
  - 中继地址与连接状态（只读）+ 「测试连接」；
  - 目标文档不再需要配置（跟随 PS 当前活动文档）。
- 理由：这些都是**全局偏好**，不该按节点存一份；节点上少一个按钮，也少一个配错的地方。

### 明确不做

- 不做"某张卡绑定某个 PS 文档"：落层目标 = PS **当前活动文档**，删掉「目标文档」下拉。
- 不做自动写回：只有人点「发送画布」才写，覆盖/新建都由用户在那个时刻决定。
- 不保留节点类型：`ps:layer` 退场，PS 能力挂在任意图片卡片上。

### 实现要点（备忘）

1. **传什么**：选中时只送缩略图（最长边 ~1024，WebP/JPEG），点「落层」时再按需取原图，避免每次点选传几十 MB 的 PNG dataURL；缩略图按内容哈希缓存在画布内存。
2. **防抖与单飞**：连续点选只发最后一次；上一张还没发完就取消/跳过。
3. **面板后开的握手**：面板上线时主动问一次「当前选中是谁」，画布回一份；否则要重新点卡片才显示。
4. **触发条件**：选中变化 + 当前选中卡的内容变化（生成完 / 修图完）都要重发。
5. **面板瘦身**：删「AI 生成」「文档下拉」「中继地址/token」「日志（收进隐藏）」，只留当前图 + 落层 + 发送画布。
6. **插件按钮要能进配置**：现在插件的 `toolbar` 项是 `extraTools`，被宿主刻意排除在快工具白名单外（否则会被筛掉）。要让它可隐藏/可排序，得把 `extraTools` 并入「自定义工具栏」的可选列表，并给稳定 id（`ps-push` 这类），同时保证默认可见。
7. **选中顺序要留痕**：预览显示"第一个选中的"，框选时没有点击序——需要宿主在选区变化时记录顺序（点选追加、框选按位置排序），不要依赖 `Set` 迭代顺序碰运气。

### 迁移

`ps:layer` 节点 → 普通图片卡片（保留 `content` / `psDoc` / `psSelection` 等 metadata），`editTarget` 与 `isPluginImageNode` 相关分支随之删除；节点上的齿轮「设置」内容搬到「配置 → PS 节点」。

### 收尾：画布侧插件退场

v0.3 落地后，**画布侧的 PS 插件退休**。它现在干的活全部由宿主或 PS 面板接手，没有一件非它不可；插件当初存在的理由（别把 PS 逻辑写进核心）也已经不成立——中继进程、配置注入、生成预览发送本来就都在宿主里。

**顺序不能跳**（跳了会和新宿主打架）：

1. v0.3 在宿主里跑通（选中即预览 / 落层 / 发送画布）；
2. 宿主启动时把画布里的 `ps:layer` 转成 `image`，保留 `content` / `psDoc` / `psSelection`；
3. 发一个**退场版插件**：不再注册 `ps:layer`，不挂 `toolbar` / `nodeActions`，只在插件记录里留一句「功能已内置，请在插件市场卸载本插件」。不发这一版的话，老机器上缓存着的旧插件会和新宿主重复注册节点、工具条出现两套；
4. 删 `canvas-plugin/`、`dist/`、`scripts/sync-canvas-plugin-cache.mjs`；
5. 文档重写：`docs/安装说明.md` 砍掉「第 2 步：装画布里的插件」（4 步变 3 步），README 删「安装画布插件」整节。

**退场后的仓库形态**：只剩 `ps-uxp/`（面板）+ `scripts/install-uxp.ps1` + `docs/`。版本号只剩 UXP 面板一套（`manifest.json`），发版 = 升 manifest 版本 + 重新部署面板；本文件「发布」与 AGENTS「发布」章节里关于 tag / jsDelivr / 两套版本号对齐的规则同时作废。

**保留**：插件系统本身。《ComfyUI 节点》《Markdown 节点》等仍走插件市场；PS 只是从插件生态里移出，变成图片卡片的原生能力。

### 收尾的副作用（要提前认）

- 改 PS 逻辑要跟着画布版本发，不能独立迭代；协议已经稳定，可接受。
- 用户机器上可能还装着旧插件缓存，必须有第 3 步的退场版提示 + 卸载指引。
- 以后想给 PS 加"重"功能（批量动作、batchPlay 图层操作），天然属于 PS 面板，不属于画布插件——画布侧插件不会再有第二春。

### 落地时踩到的环境事实

- **UXP 的 `<img>` 解不了 WebP dataURL**：缩略图最初编成 webp，画布面板预览区直接全黑（状态行/标题都正常，只有图不显示）。改成 PNG 后正常。1024 边长以内的图直接透传原图，刚好绕过这个坑，所以一开始"小图能显示、大图不能"很像另一半的 bug。
- 中继对 `track` / `preview` 只保留最新一条（`COALESCE_COMMANDS`），否则面板没开时点几十下节点会攒一队旧图，一打开面板闪一遍。
- **改中继代码要重启进程**：中继是 canvas-agent 起的常驻进程，`git pull`/改文件都不会生效；用 `POST /ps-relay/stop` + `/ps-relay/start?token=...` 重启，或让 agent 重来。

## 中继协议（草案 v0.1）

- 地址：`http://localhost:23310`（端口固定，冲突时改常量）
- 鉴权：除 `/api/health` 外，请求头必须带 `X-Relay-Token`；例外是 PS 侧端点（`GET /api/next`、`POST /api/result`）——UXP 请求不带 Origin，中继对「无 Origin 的本机请求」放行，这样 PS 面板不用手填 token。画布侧端点仍然要 token + Origin 白名单。
- 编码：JSON；图片统一 `data:image/png;base64,...`

### 端点

| 端点 | 方向 | 说明 |
|---|---|---|
| `GET /api/health` | 任意 | `{ ok, version, photoshop: { connected, doc }, canvas: { connected } }` |
| `GET /api/next?timeout=25000` | PS → 中继 | 长轮询取画布命令；超时返回 `204` |
| `POST /api/command` | 画布 → 中继 | 请求 `{ command, payload }`，返回 `{ id }`（命令排队） |
| `GET /api/result?id=&timeout=25000` | 画布 → 中继 | 长轮询取命令结果；超时返回 `204` |
| `POST /api/result` | PS → 中继 | 回填 `{ id, ok, data }` 或 `{ id, ok: false, error }` |
| `POST /api/ps/request` | PS → 中继 | PS 向画布发起请求（生成/模型列表），返回 `{ id }` |
| `GET /api/ps/next?timeout=25000` | 画布 → 中继 | 长轮询取 PS 请求；超时返回 `204` |
| `POST /api/ps/result` | 画布 → 中继 | 回填 PS 请求的结果 `{ id, ok, data/error }` |
| `GET /api/ps/result?id=&timeout=25000` | PS → 中继 | 长轮询取自己请求的结果；超时返回 `204` |

### 命令

| command | 请求 payload | 返回 data |
|---|---|---|
| `docs` | `{}` | `{ docs: [{ name, width, height, layers }] }` |
| `selection` | `{}` | `{ bounds: { left, top, right, bottom } \| null, doc }` |
| `push` | `{ image, mode: "newDoc" \| "layer", doc, layerName }` | `{ doc, layer?, width?, height? }` |
| `pull` | `{ doc?, maxEdge? }` | `{ image, doc, width?, height? }` |

### 反向请求（PS → 画布）

| command | 请求 payload | 返回 data |
|---|---|---|
| `models` | `{}` | `{ models: [{ value, label }], defaultModel }` |
| `generate` | `{ prompt, model?, reference?, doc?, selection? }` | `{ image }` |
| `latest` | `{}` | `{ image, doc }`（PS 面板「从画布接收」用） |
| `sync` | `{ image, doc }` | `{ synced: true }`（PS 面板「发送到画布」用） |

- 参考图与选区：`reference` 是 base64 图；`selection` 存在时 PS 侧会把参考图裁成选区范围，结果按选区框缩放贴回。

- 图片单张上限 8 MB（base64），超出返回错误；`maxEdge` 默认 2048。
- `push` 的 `layer` 模式只新增图层，不替换、不删除任何既有图层。

## 宿主侧（aigc-studio）

- `electron/ps-relay.cjs`：中继实现本体（零依赖）；由 canvas-agent 拉起，agent 退出时一并收掉。
- `canvas-agent/src/ps-relay.ts`：提供 `GET /ps-relay`、`POST /ps-relay/start|stop`，端口固定 23310。
- 画布页面启动时调 `ensurePsRelay()`，把 `{ url, token }` 写进 `window.__RUNTIME_CONFIG__.psRelay`，插件只读这份配置：

```js
window.__RUNTIME_CONFIG__ = window.__RUNTIME_CONFIG__ || {};
window.__RUNTIME_CONFIG__.psRelay = { url: "http://127.0.0.1:23310", token: "..." };
```

- token 是 agent 配置里的 `psRelayToken`（首次生成 32 位 hex），只用于画布侧端点鉴权；PS 侧无 Origin，免 token。

- [x] UXP manifest 用 `http://localhost/` 能放行中继（端口不写进 domains；用 `127.0.0.1` 会被拒），但需要 `manifestVersion: 6` + `host` 对象 + entrypoint `icons`

- [x] 导出整幅：副本 + flatten + resize + `saveAs.png`，不弄脏原文档（实测原文档保持未修改）
- [x] 大图往返体积/耗时（256px 测试图：pull 6KB；更大尺寸待压测）
- [x] 中继进程与 PS 断开后的重连（长轮询超时 + 3s 退避重连）
- [ ] 宿主打包后中继仍可用（产物在 `electron/` 内，不需要额外依赖；Electron 41 打包待验）
- [ ] 画布侧插件在宿主里安装并联动 PS（画布需要本地 Agent 进程才能打开项目，联调时被此阻塞）

### 联调时踩到的环境事实

- UXP 插件主脚本要等面板**第一次被打开**才执行；打开后会自动连中继。
- PS 是单实例：再次启动会立即退出（exit 1），不要把它当成启动失败。
- 本机 DSH 沙箱不允许子进程写工作区以外的目录，Electron 必须 `--user-data-dir` 指到工作区内（且路径含空格要显式加引号）。
- 宿主 `vite build` 默认配置在本机会在 esbuild 临时文件删除处报 `Access is denied`；用 `--target esnext --minify false` 可绕过（仅联调用）。
