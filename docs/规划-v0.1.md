# PS 节点 · 项目规划

> 状态：草案 v0.1（2026-11-07）
> 技术细节见同目录 `设计.md`
> 一句话：**在 AIGC 画布上加一个「PS 节点」，把画布上的图推进 Photoshop，人在 PS 里精修，一键 AI 优化后贴回 PS 新图层，并同步回画布。**

---

## 1. 背景

已经看过两个开源项目，本项目是它们的"合体思路"：

| 项目 | 它解决了什么 | 本项目借用什么 |
|---|---|---|
| [comfyui-photoshop](https://github.com/NimaNzrii/comfyui-photoshop) | 把 ComfyUI 塞进 PS 面板 | 「选区 → 生成 → 回填图层」的回路形态 |
| [aigc-comfyui-plugin](https://github.com/wangming123456456/aigc-comfyui-plugin) | 给无限画布加 ComfyUI 节点 | **插件形态**：单文件 ESM、`definePlugin` 声明节点、`Content/Panel/toolbar` 三件套、`metadata` 存结果 |

区别在于方向：comfyui-photoshop 是「PS 发起」，本项目要的是「**画布发起、PS 落地**」，AI 夹在中间。

## 2. 目标与非目标

### 目标（v1 必须做到）

1. 画布上一个节点，能把当前图**推进 PS**（新文档或现有文档的新图层）。
2. 在 PS 里改完后，能**一键取回**画布，节点图更新。
3. 一键「AI 优化」：从 PS 拿当前画面 → 跑 ComfyUI 工作流 → 结果**贴回 PS 新图层**，同时回写画布。
4. 全流程有可读的状态与报错，不白屏、不静默失败。
5. 没有 PS 的环境也能用 mock 模式验证画布侧体验。

### 非目标（v1 明确不做）

| 不做 | 原因 | 何时做 |
|---|---|---|
| PS 里保存自动回传 | 要事件钩子，COM 拿不到 | M5/不做 |
| 图层级控制（混合模式、蒙版、智能滤镜同步） | 复杂度翻倍 | M5 |
| 替换指定图层而非新增 | 先保证不破坏用户文档 | M5 |
| macOS | COM 只在 Windows | 不做 |
| 多人协作 / 远程 PS | 违反本地桥的安全模型 | 不做 |

## 3. 成功标准

| 指标 | 目标 |
|---|---|
| 一次完整循环（推 → 改 → 优化 → 回） | < 90 秒（不含 ComfyUI 出图时间） |
| 首次可用所需手工步骤 | ≤ 3 步（跑桥、填 token、拖工作流） |
| 报错可读率 | 100% 的失败路径有中文文案 + 处理建议 |
| 对用户 PSD 的副作用 | 零：只新增图层，导出走副本，从不保存原文档 |
| 画布侧代码量 | ≤ 900 行 TS（不含构建产物） |

## 4. 里程碑

每期独立可验收，不通过不进下一期。

### M0 · 骨架与假数据（0.5 天）

**做什么**
- `ps-bridge.ps1` 的 HTTP 骨架：端口扫描、CORS、token、`/health`。
- mock 模式：`/ps/docs`、`/ps/push`、`/ps/pull` 全部用占位图。
- 插件骨架：`definePlugin` + 空节点 + 面板 + 三个按钮接上桥。
- 构建脚本跑通（`CANVAS_SDK` 指向本地 SDK 出 `ps.js`）。

**验收**
- 画布上建节点 → 面板显示「已连接 · mock」，绿点。
- 点推送 / 取回，节点图有变化，状态徽标正确流转。
- 停掉桥再点，出现「没找到桥」提示，画布不崩。

**风险点**：SDK 拿不到 → 这一步就可能卡住，见 R1。

### M1 · 真 PS 单向推送（0.5 天）

**做什么**
- COM 接入：`Get-PsApp` + `DoJavaScript` 封装 + JS 转义。
- `/ps/docs` 返回真实文档、尺寸、图层名。
- `/ps/push` 两种模式：`newDoc`（`app.open`）、`layer`（`doc.place` 智能对象）。
- 面板的文档下拉接真实数据。

**验收**
- PS 没开 → 点推送自动拉起 PS 并出现新文档。
- 已有文档 → 出现智能对象图层，名字为 `AI 优化 HH:mm`。
- 文档名不存在 → 404 + 中文提示，PS 不弹错误框。

### M2 · 从 PS 取回（0.5 天）

**做什么**
- `/ps/pull`：`saveAs(asCopy=true)` 导出 PNG，支持 `maxEdge` 缩放（在副本上做）。
- 拼接图层时 `duplicate + flatten + close(DONOTSAVECHANGES)`。
- 节点 `content` 更新，`resource()` 让下游节点能直接连。

**验收**
- 在 PS 里画几笔 → 点取回 → 画布节点同步。
- 导出后 PS 文档保持"未修改"状态（不弄脏、不弹保存）。
- 3000×3000 文档导出 < 3 秒。

### M3 · AI 闭环（1 天）

**做什么**
- 桥加 `/comfy/*` 反向代理（剥 `Origin`/`Referer`，透传 status/body）。
- 插件移植 `comfy.ts`：解析工作流、找文本节点与 `LoadImage`、上传参考图、轮询 `/history`、取图。
- 工作流下拉读 comfyui 插件的 `library.v1`（只读）。
- 「AI 优化回 PS」：pull → comfy.run → push(新图层) → 更新节点。

**验收**
- 选一个 SD1.5 工作流，点一次 → PS 里多一个 AI 图层，画布节点同步更新，总耗时合理。
- 关掉 ComfyUI → 502 + 「先启动 ComfyUI」。
- 工作流缺模型 → 报出缺哪个文件名（复用 comfyui 插件的预检逻辑）。

### M4 · 体验与安全（1 天）

**做什么**
- 设置面板：桥地址、token、`maxEdge`、图层命名模板。
- 端口自动扫描 + 缓存失效重扫。
- 进度与耗时、取消按钮（AbortController）。
- 日志改善：桥控制台可读、错误带 hint。
- Origin 白名单（可选）。

**验收**
- 换端口重启桥，插件自动重连，无需手动改配置。
- 优化中途点取消 → 桥不再等待，PS 不留半成品。

### 可选 · M5（本期不做）

替换指定图层、蒙版同步、PS 动作（Action）触发、macOS（需换 UXP 路线）。

## 7. 风险登记

| # | 风险 | 概率 | 影响 | 应对 |
|---|---|---|---|---|
| R1 | 宿主 SDK 拿不到，插件只能"盲写" | 高 | 高 | 按 `comfyui.js` 反推的 API 写；交付时附「拿到 SDK 后 3 处必改」清单 |
| R2 | 本机没有 PS，M1 起无法验证 | 高 | 高 | M0 用 mock 把画布侧做扎实；M1 交付「启动说明 + 自测清单」 |
| R3 | 桥对任意网页开放，等于把 PS 交出去 | 中 | 高 | 默认 token 鉴权；文档写明不要暴露公网；M4 加 Origin 白名单 |
| R4 | `DoJavaScript` 版本差异导致调不通 | 中 | 中 | 三级回退：`$null` → `@()` → `DoJavaScriptFile` |
| R5 | 中文路径 / 大 PSD 导出超时 | 中 | 中 | 临时文件放 `%LOCALAPPDATA%`；副本缩放 + 30s 超时 |
| R6 | 两插件共用 storage 键产生耦合 | 低 | 低 | 只读 `library.v1`，读不到就提示重新导入 |

## 8. 跨机器部署

开发和运行不在同一台机器：**本机（没有 PS / ComfyUI）写代码，另一台（都有）跑**。这带出四条硬约束：

| 约束 | 说明 |
|---|---|
| **浏览器和桥必须同一台机器** | 插件请求的是 `127.0.0.1`，画布页面也得在那台机器的浏览器里打开。跨机要改绑 `0.0.0.0` + token + 防火墙，排到 M5 |
| 脚本必须兼容 Windows PowerShell **5.1** | 运行机不一定装了 PowerShell 7；禁止用 `??`、三元运算、`-Parallel` 这些 7.x 语法 |
| `.ps1` 必须存成 **UTF-8 带 BOM** | 5.1 默认按 ANSI(GBK) 读文件，没 BOM 的中文会直接解析报错（本项目已踩过一次） |
| 数据目录要可配 | 默认 `%LOCALAPPDATA%\ps-bridge`，加 `-DataDir` 参数，方便换盘或受限环境 |

### 拷贝清单

整个 `PS节点\` 目录拷过去即可（`node_modules` 不用拷）：

```
PS节点\
  bridge\check-env.ps1     ← 到那台机器先跑这个
  bridge\ps-bridge.ps1     ← M0 产出
  bridge\start.cmd
  plugin\src\...           ← 构建源码
  plugin\ps.js             ← 构建产物（带了 SDK 就能自己构建）
  规划.md / 设计.md
```

### 落地顺序

1. 运行机跑 `check-env.ps1`（先不加参数；再 `-StartPhotoshop` 实测 COM + ExtendScript 通道）。
2. 构建 `ps.js`：有 Node + SDK 就自己构建，否则把构建产物直接拷过去。
3. 启动桥 → 浏览器打开画布 → 插件市场填本地文件或 jsDelivr 地址。
4. 按 `设计.md` §6 的用例逐条验收（M0 那批不需要 PS）。

### 哪些我在这边能验、哪些只能你那边验

| 能力 | 本机 | 运行机 |
|---|---|---|
| 桥的 HTTP / 路由 / token / mock | ✅ 能验 | ✅ |
| PS COM / ExtendScript | ❌ 没装 PS | ✅ |
| ComfyUI 代理 | ❌ 没装 | ✅ |
| 插件构建（`tsc` + esbuild） | ❌ 没 SDK | 取决于 SDK |
| 画布内 UI 自测 | ❌ 没 SDK | ✅ |

> 结论：**M0 的桥和插件逻辑我在这边就能验**（mock 模式），M1 之后必须靠那台机器。每期交付时我会附一条"在那台机器上跑这几条命令"的自测清单。
